# 四半期ロードマップ照合

## 入力

- 対象四半期（例: `2026Q2`）。4月始まりの年度で、Q1=4〜6月、Q2=7〜9月、Q3=10〜12月、Q4=翌年1〜3月。指定がなければユーザーに確認する。
- フォルダのパスは `utils/config.ini` の `[Path]` から読む（`daily_path`、`weekly_path`、`quarterly_path`）。保管フォルダのルートは `daily_path` の親フォルダ。
- ロードマップ: `<保管フォルダ>/99_Document/ロードマップ2026-2027.md` の対象四半期の表（目標・アクション・完了条件）と「この期にやらないこと」。

## 手順

1. **日誌のタグ付き行を抽出する**。対象期間の `01_Daily/YYYY-MM-DD.md` から、`#移譲 #対人 #開発 #評価 #トラブル #説明` のいずれかが付いた箇条書きを抜き出す（タグだけで本文がない行は除く）。出力が大きいので、ツールの結果をファイルに保存してから読む。

   ```bash
   cd "<daily_path>" && for f in $(ls | awk '$0>="<開始日>" && $0<"<終了日の翌日>"'); do
     grep -E "^\s*- .*#(移譲|対人|開発|評価|トラブル|説明)" "$f" | grep -vE "^\s*- #\S+\s*$" | sed "s/^/${f%.md} /"
   done
   ```

   あわせて、タグ別の件数と最初の日付を数える（日誌がない月があれば結果に明記する）。
2. **週次振り返りを読む**。`02_Weekly/<開始>_<終了>_weekly.md` のうち、開始日が対象期間内のものをすべて読む（「優れた仕事」「お粗末な仕事」「改善すべきこと」を根拠に使う）。
3. **完了条件ごとに判定する**。
   - 進捗率は完了条件の数値部分に対する達成度で出す。条件が2つある項目は平均する。
   - 日誌・週次に記録がない成果物（台帳、計測データなど）は「根拠不明」として0%扱いにする。推測で補わない。
   - 根拠には日付（週次は「8/31週」の形）を付けて具体的に書く。
   - 「この期にやらないこと」に反する記録があれば根拠欄で指摘する。
4. **仮説の修正を書く**。未達の原因を週次振り返りの繰り返しパターン（同じ問題が複数週に出ているか）から探し、次四半期に変える行動を1項目1行で書く。後の四半期の完了条件が今期の成果を前提にしている場合は、その影響も書く。
5. **書き込む**。`<quarterly_path>/<対象四半期>_quarterly.md` の「### 判定結果」の表と「### 次四半期へ持ち越す仮説の修正」を置き換える。ファイルがなければ、WorkScribe の「四半期レビューを作成」で先に作ってもらうよう伝える。

## 出力形式

```markdown
### 判定結果

- 対象データ：日誌 <最初の日付>〜<最後の日付>（<日数>日、タグ付き<件数>件：<タグ別件数>）、週次振り返り<週数>週分（<期間>）。
- 判定方法：完了条件の数値部分に対する達成度。条件が2つある項目は平均。日誌・週次に記録がないものは「根拠不明」として0%扱い。

| ロードマップ項目 | 完了条件 | 進捗率 | 根拠 |
| --- | --- | --- | --- |
| <目標> | <完了条件> | <%>（<内訳>） | <日付付きの根拠> |

### 次四半期へ持ち越す仮説の修正
- **<テーマ>**：<成り立たなかった仮説と根拠>。<次四半期に変える行動>。
```

## 注意

- 業務日誌の保管フォルダは WorkScribe のリポジトリ外なので、書き込んでもコミットは不要。
- 回答は日本語。最後に項目ごとの進捗率の要約表を示す。
